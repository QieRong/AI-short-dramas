### 事故 1：git filter-repo 清历史导致工作区 IP 文件丢失（2026-10-10）

**操作**：执行 `git filter-repo --invert-paths` 清除历史中的 4 个 IP 文件。

**预期**：仅清理 git 历史，工作区文件保留。

**实际**：filter-repo **重写了全部 ref（含预先创建的 `backup-before-clean` 备份分支）**
并**重置了工作区**，导致：

1. 4 个 IP 文件从工作区消失
2. 备份分支被一并重写，**失去保护作用**
3. `refs/original/` 未保留，旧对象被回收，本地无法恢复
4. 未提交的 `.gitignore` 改动被回退，**IP 保护规则静默失效**

**恢复过程**：远程仓库尚未强推，原始历史（`f6627cd`）完整，故从远程 fetch 后
`git checkout` 成功取回 4 个文件，哈希逐一比对**完全一致，无内容丢失**。

**教训记录（必须遵守）**：

1. **git 层面的备份在 filter-repo 面前完全无效**——分支 / tag / refs/original 都会被重写或清理。
2. **任何"清历史"操作前，必须先做仓库外物理备份**：`cp -r <项目> <项目外目录>`。
3. **`refs/original/` 不可依赖**——filter-repo 完成后会清理，`git gc` 也会回收。
4. **清理后必须重新校验 `.gitignore`**——filter-repo 重置工作区会回退未提交的改动，
   导致保护规则静默失效（本次 IP 目录一度显示为未跟踪 `??`，若不复查将导致再次泄露）。
5. 本次物理备份位置：`E:\WorkBuddyTask\_backup_AISD_20261010\`（含完整 `.git`）。
